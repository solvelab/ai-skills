## [2.0.0](https://github.com/solvelab/ai-skills/compare/v1.21.1...v2.0.0) (2026-08-06)

### ⚠ BREAKING CHANGES

* **documentation:** the skill no longer always produces three documentation
tiers. README.md is the only unconditional document; every other file is
earned via the decision table, and the skill must say when it deliberately
produced only a README.

The skill instructed two opposite policies. The frontmatter description --
always in context, and what drives selection -- promised "ALWAYS creates all
three documentation tiers", while the body ordered "Do NOT create documents
that don't apply" and Troubleshooting restated the first claim. Three
statements, two incompatible policies.

Measured on a real undocumented 1,432-line Python service, same task and
reference files, output scored against the source:

                              current    revised
  documents created              5          4
  documentation lines          873        786
  env vars documented/in code  16/16      16/16
  endpoints documented/in code  6/6        6/6
  machine-checkable claims      84        131
  claims failing verification   13         11
  failure rate                15.5%       8.4%
  states what it could not verify  no      yes

Both arms read the code correctly -- the old text was sound on accuracy and
wrong on scope. A claim checker over production repos also found a README
directory tree written without its src/ prefix: 9 of 10 entries unresolvable,
one naming a file renamed months earlier, in the artifact the skill mandated
most insistently.

Adds the doctrine the file had no rule for: one purpose per page (how-to
content decays faster than why content, so a page mixing them decays at the
speed of its fastest half), every claim must be checkable, keeping it true
(same-commit rule, named owner, dated volatile facts), and AGENTS.md.

The AGENTS.md trigger is itself a simulation result: conditioning on "repo is
worked on by AI coding agents" produced the file in zero runs because the
condition is not observable from a checkout. Keyed on a detectable file
(CLAUDE.md / .cursorrules / copilot-instructions.md) it fires, and the run
also collapsed the duplicate CLAUDE.md into a pointer.

SKILL.md 543 -> 174 lines; skeletons, formatting conventions and changelog
format move to references/templates.md. Drops the "How to Use" and "Trigger
Test Cases" meta sections and collapses 14 badge mentions into one
signal-only rule.

documentation 2.1.0 -> 3.0.0.

## [1.0.0] - 2026-07-01

### Added

- Canonical `skills/` directory following the open Agent Skills standard — every skill is a
  self-contained folder (`skills/<name>/SKILL.md` + optional `references/`), installable by
  `npx skills add solvelab/ai-skills` across 70+ agents.
- Claude Code plugin + marketplace manifests (`.claude-plugin/plugin.json`,
  `.claude-plugin/marketplace.json`): install with `/plugin marketplace add solvelab/ai-skills`.
- Automated releases: semantic-release on every push to `master`
  (`.github/workflows/ci.yml`) — version computed from Conventional Commits, propagated
  to `VERSION` and the plugin manifests by `scripts/set-version.sh`, changelog and GitHub
  Release generated, `vX.Y.Z` tagged.
- CI validation (`.github/workflows/ci.yml`): wrapper sync, version coherence,
  frontmatter checks.

### Changed

- `shared/skills/*/content.md` merged into `skills/<name>/SKILL.md`; `game/r3f-*` flattened
  to `skills/r3f-*`.
- `claude/`, `codex/`, `cursor/`, `copilot/` wrappers are now generated from `skills/` by
  `generate.sh` (kept for backward compatibility with existing installs).
- `install.sh` defaults to native symlink install into `~/.claude/skills/` (no `CLAUDE.md`
  edit needed); `--legacy` keeps the old CLAUDE.md block behavior.

# Change: Make the Lua track's example runnable and its declaration re-measurable

## Why

`skills/bug-hunter/references/track-fivem-lua.md` prescribes and does not demonstrate. It tells the
reader that, with no generator and no scorer in the ecosystem, the boundary witnesses have to be
written by hand — *"for every limit the code enforces, a case on each side and one at the value"* —
and shows not one line of how. The Python track shows: it carries a `hypothesis` block and a
`cosmic-ray` block. The Lua reader gets the doctrine and no form.

The same file also carries three probed claims, each dated 2026-09-07: `lua-quickcheck` supports only
Lua 5.1 and 5.2, no mutation rock exists, and `busted` needs a second install step. The track itself
says *"Re-run that one line before believing this paragraph — it is a fact with a date, and a rock
supporting 5.4 could appear."* Nothing re-runs it. A dated fact nobody re-measures decays into the
guessing `verify-before-claiming` exists to refuse.

The two are one problem: an example nobody executes rots exactly like a claim nobody re-measures.

## What Changes

- The track gains a minimal, runnable example: a pure Lua module with one limit and the `busted` spec
  that proves the limit on each side and **at the value** — the witness the section demands.
- `scripts/probe-lua-track.sh` extracts those blocks **from the published track**, runs them, and
  re-runs the three ecosystem claims, failing and naming whichever stops holding.
- The script also proves the witness rather than only the example: it moves the limit constant by one
  and requires the suite to go red. An example that passes but catches nothing demonstrates nothing.
- `bug-hunter` → 2.7.0.

The script is a maintainer command, not a CI gate: it needs `luarocks`, the network and a rock
install, and a gate on those fails this repository's builds on a third party's availability. Its
header says so, in the shape `scripts/validate-rite.sh` and `scripts/validate-skill-version.py`
already use.

# Change: Give bug-hunter a generation and scoring layer

## Why

`bug-hunter` is the catalog's adversarial-testing rite and eighteen skills and agents defer their
testing gate to it (`grep -rl 'bug-hunter' skills/*/SKILL.md agents/*.md`). Both of its pieces —
`skills/bug-hunter/SKILL.md` and `agents/bug-hunter-analyst.md` — work **entirely by enumeration**:
a human or an agent lists the scenarios it can imagine, one at a time.
`grep -riE 'property-based|hypothesis|mutation|metamorphic|fault injection' skills/bug-hunter/`
returns nothing. The only place in the catalog where automatic generation appears is
`skills/api-resilience-testing/SKILL.md:205-209` (Schemathesis/Hypothesis), and there it is scoped
to REST schema fuzzing — it never reaches the general rite.

Two consequences, both visible in the skill's own history:

1. **Enumeration finds only what the author can imagine.** The skill's *"Why these five were added"*
   table is the proof: shape, fragmented input, distinctness, observable degradation and burst all
   entered **after** a field defect escaped. The growth mechanism is post-hoc by construction.
2. **Nothing inside the change says the hunt was thin.** The exit criterion is "every applicable
   scenario exists as a test and is green". Green over cases the author chose proves the author's
   assumptions — `agents/bug-hunter-analyst.md` says exactly that in *When to invoke*. Nothing
   measures whether those tests would kill the defect.

This repository is its own witness. `scripts/selftest-validate-agents.py` was green at 22/22 when
`bug-hunter-analyst` was pointed at the validator that shipped it and returned six defects the
selftest did not cover (issue #205). A green example-based suite and an effective one are not the
same object, and the rite currently has no way to tell them apart.

## What Changes

- `bug-hunter` → 2.5.0. A new section separating three things the rite currently conflates:
  **enumerate** (what the checklist already does), **generate** (attacks nobody listed) and
  **score** (whether the hunt caught anything). Each technique carries the condition under which it
  pays and a `lean:` ceiling, so a small change is not made to carry a mutation run.
- `references/track-python-pytest.md`: the concrete command for the Python ecosystem, scoped to the
  module the change touched, **and the plausible-but-wrong command named** — required by
  `skills-authoring`, *"A prescribed step carries its command"*.
- `agents/bug-hunter-analyst.md`: the output contract gains candidate invariants, keeping `ATTACKS`,
  `TESTS TO WRITE` and `TRIED AND FOUND NOTHING` unchanged.

Every number published by this change was measured on this repository during it, against its own
validators; the two web searches that motivated the item are recorded as motivation, never as
evidence. Where a technique produced nothing, the change says so instead of quoting a study.

### New Capabilities

### Modified Capabilities

- `skills-catalog`: ADDED requirement — the adversarial rite SHALL distinguish enumerating,
  generating and scoring, and every technique it prescribes SHALL carry the condition under which
  it pays, measured on this catalog rather than cited.
- `agents-catalog`: ADDED requirement — an agent that applies a skill's methodology SHALL carry a
  layer added to that methodology, or the change SHALL say why it does not, without displacing the
  section that reports what produced nothing.

## Impact

- Affected skills: `bug-hunter` (SKILL.md + `references/track-python-pytest.md`). No other skill's
  content changes; the eighteen that defer to it inherit the wider rite without editing.
- Affected agents: `bug-hunter-analyst` (canonical `agents/`, mirrored into `plugins/testing/agents/`).
- Generated trees `claude/`, `codex/`, `cursor/`, `copilot/`, `plugins/` are regenerated by
  `./generate.sh`; none is edited by hand.
- No catalog composition change: no skill added, removed or renamed, so `npx skills add --list`
  discovery and the README trigger table are untouched.
- `references/track-fivem-lua.md` and `references/track-dotnet-plugin.md` are deliberately NOT
  changed: neither ecosystem's tooling was measured here, and prescribing an unprobed command is the
  failure this change exists to prevent.
